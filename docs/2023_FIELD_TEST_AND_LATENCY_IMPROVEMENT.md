# 2023년 라인트레이서: 사람 인식 정지 시험과 지연 문제 해결 과정

> **근거 구분:** 이 문서는 사용자가 2026-10-31 대화에서 직접 설명한 **2023년 실제 장치 시험·개선 경험**을 정리한 2026년 회고 기록입니다. 해당 동작을 수행한 최종 Arduino/Python 소스 원문이나 지연 측정 로그는 아직 확보하지 못했습니다. 아래 경험 사실과 `main`의 2026년 재구성 소스는 같은 것이 아닙니다.

## 프로젝트의 실제 목적

사용자가 2026-10-31 추가로 확정한 목적은 **특정 적재 구간에서 사람이 대기 중인 경우에만 정지**하는 것입니다. Pi는 사람 존재 여부만 0/1로 계산해 보내고, **아두이노가 해당 구간을 감지해 최종 정지를 담당**했습니다. 해당 구간이라고 무조건 멈추거나, 다른 곳에서 사람이 검출됐다는 이유만으로 정지하는 것이 아닙니다. 적재를 마치면 버튼으로 재출발하는 기능을 추가한 과제입니다.

## 사용자 직접 확인: 시험 결과

- **실제 장치 시험 성공:** 카메라 사람 인식 결과와 라인트레이서의 정지 동작을 연결해, **사람이 인식되면 정지**하도록 동작하는 것을 확인했습니다.
- **초기 발생 문제:** 사람 인식을 추가하면서 연산량과 처리 지연이 커져, 정지 신호가 늦게 반영되어 로봇이 **목표 정지 구간을 지나치는 현상**이 나타났습니다.
- **개선 1 — 연산 간소화:** 사람 인식에 필요한 처리만 사용하도록 연산을 줄였습니다. 다만 어떤 함수·연산을 몇 개 줄였는지, 처리 시간이 얼마나 개선됐는지는 원문·실측 로그로 확인되지 않습니다.
- **개선 2 — 감지 시점 선행:** 정지 구간에 도달하기 전에 **조금 더 앞에서 사람 감지를 시작**하도록 조정했습니다. 정확한 거리·구간 길이 및 센서의 물리적 위치 변경 여부는 확인되지 않았습니다.
- **개선 3 — 적재 후 재출발:** 적재가 끝난 뒤 **버튼을 다시 누르면** 일정 시간 동안 **사람 인식 신호와 색상 정지구간 조건 모두 정지 판단에서 무시**하고 IR 라인트레이싱을 유지하도록 구성했습니다. 1~3초 범위를 시험했으며 최종 고정값은 미확인입니다.

위 항목은 사용자가 실제 개발·시험 및 조치를 직접 확인한 결과입니다. 별도의 성능 수치가 없으므로 성공률, 정지 거리, 지연시간 개선율 등을 새로 만들지 않습니다.

## 문제해결의 논리

```text
기존 IR 라인트레이서
       │
       ▼
Safe Watch의 사람 검출 부분만 추출하여 Raspberry Pi에 적용
       │
       ▼
Arduino와 Pi의 시리얼 신호 연동 → 사람 인식 시 정지 시험 성공
       │
       ▼
[문제] 영상 검출 연산으로 제어 응답 지연 → 목표 적재 정지 지점 초과
       │
       ├─ 필요한 검출 연산 간소화
       └─ 정지 지점보다 앞선 시점에서 감지 시작
       │
       ▼
적재를 위해 정지
       │
       ▼
적재 완료 후 버튼 재입력
       │
       ▼
사람·색상 두 정지 조건 모두를 일정 시간 무시 → 기존 IR 라인트레이싱 재개
```

**정지 지점의 조기 감지는 연산 시간을 줄이는 최적화와 별개로, 시스템의 검출·결정·제어 지연을 고려해 위치/시점을 조정한 조치**입니다. 이는 사용자의 설명을 구조적으로 해석한 것이며, 당시 구현한 정확한 시간 제어 알고리즘을 의미하지 않습니다.

## 2026년 공개 복원 코드와의 차이

| 항목 | 사용자 확인에 따른 2023년 실제 경험 | 현재 2026년 재구성 코드 |
|---|---|---|
| 지정 구간 대기자 → 정지 | **사람 대기 시 정지하도록 실제 시험 성공** | 이전 복원본의 색상 단독 정지 문제를 AND 조건으로 교정했지만, 2023년 최종 원문과 동일 여부 미확인 |
| 영상 처리 최적화 | **간소화 조치 실시** | 실제 최적화된 원문 전체가 없어 동일한 연산 경로를 보장할 수 없음 |
| 정지 지점 이전 인식 | **먼 시야에서 반복 검출, 0.3초 갱신** | Pi 복원에서 0.3초 주기 사용. 추론 지연이 크면 실제 간격이 길어질 수 있음 |
| 적재 후 버튼 재출발 | **정지 상태는 버튼 전까지 유지** | Arduino 복원에서 버튼으로 해제하도록 처리 |
| 일정 시간 무시 범위 | **사람 신호·색상 조건 모두 정지 판단에서 무시한다고 직접 확인** | Arduino 복원은 무시 기간에 색 센서 및 사람 신호로 정지하지 않고 IR 주행. Pi 촬영 자체는 지속하도록 복원 |

2026년 복원본의 Pi·Arduino 역할 혼합 문제를 수정하고, 0.3초 인식값 갱신과 두 조건 무시를 추가 반영했습니다. 하지만 이것을 실제 2023년 최종 스케치와 완전히 일치하는 코드라고 주장해서는 안 됩니다.

## 근거 자료 및 남은 불확실성

- 새로 제출된 2023년 Arduino 개발 스케치 여러 버전(실험적 `r>=5 || receivedNumber>=1`, `receivedNumber!=0` 정지 등)은 색상·사람 조건과 주행 제어를 연결하려 했음을 뒷받침하지만, **최종 실행한 버전**은 아직 미확인입니다.
- Arduino–Pi 시리얼 송수신 시험 사진 및 Safe Watch 검출기 재사용 사진은 개발 과정을 보여줍니다. **최종 사람 인식 정지 성공은 사용자 직접 확인**에 근거하며, 공개 사진만으로 성공률을 산정하지 않습니다.
- 사람 감지의 정량 인식률, 정지 소요 거리·시간, 최적화 전후 연산 비용, 정확한 적재 위치, 실제 테스트 횟수, 최종 프로토콜은 확인되지 않았습니다.

## 직무 관련 경험 서술

“Arduino 기반 라인트레이서에 기존 영상 인식 기능을 재사용해 Raspberry Pi와 연동하고, **사람 인식 시 정지하는 동작을 실제 시험으로 확인**했습니다. 영상 처리 지연으로 정지 지점을 지나치는 문제가 발생해 **검출 연산을 간소화하고 감지 시점을 앞당겼으며**, 적재 완료 후 버튼 입력 시 **사람 신호·색상 정지 조건을 모두 일정 시간 무시해 주행을 재개**하도록 개선했습니다.”

이 설명은 본인의 직접 경험을 기반으로 하며, 현재 복원 소스의 검증 상태와는 별도입니다.
