# Raspberry Pi 촬영 시점 — 2023년 대화 흔적 재검토

## 결론

**정지구간에 도착한 뒤 촬영을 처음 시작한 것이 아니라, 구간에 도착하기 전부터 프레임을 반복 추출하고 사람 검출을 수행한 뒤 RGB/버튼과 결합했다는 근거가 더 직접적입니다.**

아래는 2023년 당시 사용자 대화에서 확인된 **부분 흐름**입니다. 전체 원문 파일을 복원한 것은 아닙니다.

| 시점 | 확인된 입력 또는 답변 | 해석 |
|---|---|---|
| 2023-11-21 | Pi의 기존 반복 루프에서 `get_frame(ip)` 다음 `count_objects.detect()` 실행 | 카메라 촬영·사람 검출이 반복 처리의 한 부분 |
| 2023-11-23 16:54 | 사용자가 제시한 `main.py`: `while True`에서 `get_frame(ip)` → `count_object()` → 인원 출력 → `send_data_to_arduino(...)` → `ser.readline()` | 구간 센싱을 기다리는 조건문 없이 먼저 촬영·검출 |
| 2023-11-24 13:46 | 사용자가 색상값은 시리얼로 수신하고 사람 수는 `count_objects`에서 얻는다고 설명 | 사람 인식과 구간 센서는 별도 입력 |
| 2023-11-24 13:51 | 수정 제안 흐름도 `get_frame(ip)` → `people_num, _ = count_object()` → `get_serial_data()`로 RGB·버튼 수신 → 결과 판정 | 사진 촬영은 RGB 구간 조건보다 앞에 배치 |

## 두 가설 비교

**A. 구간에 도착한 뒤 촬영 시작**: 해당 방식의 실제 2023년 `if color_condition: get_frame(...)` 코드 기록은 발견되지 않았습니다. 이는 기존 2026년 복원본이 가정한 순서였고, 현재 사용자 설명과도 맞지 않습니다.

**B. 주행 중 반복 촬영·사람 검출 → 구간 센싱 시 두 조건 결합**: 당시 사용자 코드는 반복 촬영·검출을 지지합니다. 사용자 최종 확인에 따르면 **Pi는 사람 존재 0/1만 송신하고 Arduino가 정지구간을 센싱해 두 조건을 결합**했습니다. 이 역할 분담이 실제 구현입니다.

## 과거 프레임 소스의 추가 확인

2023년 11월 23~28일 사용자 `main.py`에서는 `get_ip()`가 `netifaces`로 `wlan0` IPv4 주소를 확인하고, `get_frame(ip)`가 `http://<ip>:8000/stream.mjpg`에서 `cv2.VideoCapture`로 프레임 하나를 읽어 `before.jpg`로 저장합니다. 이 **스트림에서 한 장씩 추출하던 경로**가 확인됐으므로, 이전 2026년 복원본의 `Picamera2.capture_array()` 단독 구현보다 직접적인 근거가 있습니다. `raspberry_pi/main.py`도 이제 해당 함수 흐름을 반영합니다. 이 URL이 인터넷 공개 스트리밍을 의미하는 것은 아닙니다.

실제 사용자 코드의 `/home/pi/project/before.jpg`와 Safe Watch 검출기 원본의 `/home/pi/project/image/before.jpg` 사이 차이가 있었고, 관련 이미지 읽기·쓰기 오류가 보고됐습니다. 현재 복원본에서는 함수 간 경로를 **일치시키기 위해 후자를 선택**했습니다. 이 선택은 2023년 최종 경로를 확정한다는 뜻이 아닙니다.

## 정확히 확정할 수 없는 것

- 카메라 영상을 계속 저장·녹화했다는 의미는 아닙니다. `get_frame()`이 스트림에서 한 프레임을 가져와 `before.jpg`로 저장하는 동작을 **반복**한 흔적입니다.
- 사람을 매 프레임 추론했는지, 1초 단위 등 지정된 간격마다 추론했는지의 최종 반복 주기는 미확인입니다.
- 사람 인식 수치를 이전 반복에서 따로 `cached_people_num`으로 보관했는지, 현재 반복에서 계산한 값을 바로 썼는지 미확인입니다. 2023년 코드 조각은 **촬영→감지→구간 데이터와 결합**의 순서만 뒷받침합니다.
- 정지 구간 이전의 조기 검출 시점과 실제 정지 지점의 거리, 카메라 ROI, 버튼 재출발 후 인식 무시 방식은 최종 코드 원문이 없어 확정할 수 없습니다.
- 과거 문답에 남은 `색 OR 사람` 조건은 사용자가 밝힌 목적(구간 AND 대기자)과 충돌하므로 원문은 별도 보존하고, 현행 실행용 복원은 AND 조건을 사용합니다.

## 현재 복원본 처리 흐름 (최종 역할 반영)

```text
Raspberry Pi 반복: get_frame → before.jpg → count_objects.detect
                      ↓
                 people_num을 0/1로 이진화
                      ↓
                Arduino로 존재 플래그 송신
                      ↓
Arduino: TCS34725로 정지구간 감지 → 사람 존재 플래그와 AND
                      ↓
               정지·적재 후 버튼 재출발
```

현재 코드는 **2026년 역할 분담 복원본**이며 실제 2023년 전체 파일이 아닙니다.
