# 2023년 프로젝트 촬영·정지 흐름과 미확인 부분

## 2023년 대화에서 확인된 반복 구조

**Raspberry Pi는 주행 중에도 카메라 스트림에서 프레임을 반복 추출해 사람 수를 계산했습니다.** 2023-11-23 사용자가 제출한 `main.py` 부분 흐름은 `while True` → `get_frame(ip)` → `count_object()` → `send_data_to_arduino(...)` → `ser.readline()`입니다.

2023-11-24에 논의한 수정 흐름도 먼저 `get_frame(ip)` → `count_object()` 실행 후 RGB·버튼 수신값을 판정합니다. **색상 정지구간 도달 후에야 카메라를 처음 구동한다는 코드 흔적은 찾지 못했습니다.**

```text
기존 Arduino IR 라인 추종 (주행 유지)
         │
Pi 반복 촬영 → before.jpg → count_objects.detect()
         │
   최신 사람 검출 결과(people_num)
         │
 Arduino에서 RGB/버튼 수신
         │
   TCS34725 정지구간 조건?
         ├─ 아니요: 기존 주행 유지
         └─ 예
              ├─ 사람 없음: 기존 주행 유지
              └─ 사람 있음: 정지·물품 적재 대기
                                  │
                          버튼으로 재출발
                       (색상 정지구간 잠시 무시)
```

## 주의할 부분

- **반복 스냅샷 방식**이지 전체 영상의 매 프레임을 항상 분석했다는 증거는 아닙니다.
- 사람 검출 결과를 따로 장기 캐싱했는지, 매번 새 결과를 바로 사용했는지는 명확하지 않습니다. 현재 `raspberry_pi/main.py`는 최신 반복 결과를 즉시 사용하도록 보수적으로 복원했습니다.
- 감지 시작 지점을 앞당겨 영상 연산 지연에 대응한 실제 경험은 확인되지만, 그 구간과 정지구간의 센서 위치/간격 및 최종 제어 코드는 미확보입니다.
- 검출 영역(ROI), 실제 주기, 사용한 최종 색상 환산식, `0/1` 회신 의미는 코드 버전마다 다르며 최종 통합 조합 미확인입니다.

## 원문과 목적 복원의 차이

2023년 대화에 남은 `색 OR 사람` 판단식은 실제 목표인 `색 AND 사람`과 충돌합니다. 실행용 복원은 사용자가 직접 확인한 목적을 반영한 **AND** 조건을 사용하고, 과거 `OR` 조건은 [분석 문서](CONTROL_LOGIC_AUDIT.md)에 그대로 보존했습니다.
