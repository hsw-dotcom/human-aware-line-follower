# 사람 감지와 정지 결정의 논리적 영향 분석

> 분석 대상: `raspberry_pi/main.py`의 **2026년 대화 기록 기반 복원 코드**입니다. 2023년 실제 실행 원문이 없으므로 당시 최종 시스템이 같은 문제를 보였다고 단정하지 않습니다.

## 확인된 기록 속 최종 판단식

```python
color_condition = r >= 4 or r >= 2 * g or r >= 2 * b
if button == 1:
    result = 1
elif color_condition or people_num != 0:
    result = 0
else:
    result = previous_result
```

이 함수 자체는 **색 구간이 아니더라도 사람 수가 0이 아니면 정지**할 수 있습니다. 그러나 현재 복원본의 `LineTracerState.process()`는 **색 조건이 참인 경우에만** `detect_people()`를 호출하고, 그 밖에는 `people_num = 0`으로 둡니다. 따라서 전체 호출 경로를 같이 평가해야 합니다.

## 복원본 실제 제어 경로 (버튼 미입력, 감지 무시 시간 종료 가정)

| 색 조건 | 사람 감지 호출? | 가정된 감지 결과 | 반환 결과 | 이유 |
|---|---|---|---|---|
| 거짓 | 아니요 | 항상 0(기본값) | 이전 상태 유지 | 사람 감지 자체를 실행하지 않음 |
| 참 | 예 | 0명 | **정지(0)** | 색 조건만으로 정지 |
| 참 | 예 | 1명 이상 | **정지(0)** | 색 조건만으로 이미 정지 |

**결론: 현재 복원본의 정지 출력은 사람이 0명인지 아닌지에 따라 달라지지 않습니다.** 따라서 현행 복원 코드만을 근거로 '**사람이 있을 때만 정지하는 시스템**'이라고 설명하면 안 됩니다.

또한 `r=g=b=0`인 경우 비교식 `r >= 2*g`, `r >= 2*b`가 참이어서 **색 감지 조건이 참**이 됩니다. 그 경우 실제 센서 상태·시리얼 변환 규칙은 확인되지 않았습니다.

## 설계 의도와 원본의 공백

- 기록에는 특정 바닥색 구간에서 사람을 감지하고 정지하는 목표가 언급되어 있습니다.
- 하지만 남아 있는 최종 판단식은 **색 또는 사람**을 정지 조건으로 묶습니다.
- 어느 단계에서 검출을 시작했는지, 사람 수가 실시간으로 갱신됐는지, 실제 정지 트리거가 색인지 사람인지 구별하는 원본 로그는 없습니다.
- 이를 임의로 `색 AND 사람`으로 바꾸거나 항상 사람 감지를 수행하는 것으로 고치면 현재 보존한 사용자 설명과 달라집니다. **그런 변경은 후대의 별도 대안 설계로 표시**하고, 2023년 원본이라고 주장하지 않아야 합니다.

## 필요한 추가 증거

당시 Arduino/Pi 원본, 시연 영상, 색 센서의 실제 r:g:b 값과 사람 수·Pi 반환값이 함께 나오는 로그가 있으면 이 판단을 개선할 수 있습니다. 현재는 **제어 규칙을 복원한 연구 기록**으로 소개하는 것이 타당합니다.
