# 특정 구간의 대기자 조건 — 실제 목적과 역사적 판단식

## 사용자 최종 확인 (2026-10-31)

**특정 적재 구간에서 사람이 대기하고 있을 때만 라인트레이서가 멈추는 것이 목적**입니다. 해당 구간에 사람이 없으면 계속 주행하고, 구간 밖 사람을 검출해도 그 이유만으로 정지하지 않습니다.

| 적재 구간 | 대기자 인식 | 이전 주행 상태 1일 때 동작 |
|---|---|---|
| 밖 | 없음/있음 | 1: 계속 주행 |
| 안 | 없음 | 1: 계속 주행 |
| 안 | 있음 | **0: 정지·적재 대기** |

정지 후에는 사람이 사라져도 정지 상태 0을 유지하고, 적재 후 버튼으로 1을 회신하여 재출발합니다. 재출발 때 특정 시간 동안 **색상 정지 구간을 무시**했다고 사용자 경험으로 확인됐습니다.

## 과거 대화에 남은 판단식 — 역사적 기록 (수정 없이 보존)

```python
color_condition = (r >= 4 or r >= 2*g or r >= 2*b)
if button == 1:
    result = 1
elif (color_condition == 1 or people_num != 0) and button == 0:
    result = 0
else:
    result = previous_result
```

`OR` 조건은 대기자가 없더라도 색 조건만 참이면 정지하므로 사용자가 명확히 밝힌 실제 목적에 맞지 않습니다. 이 식이 최종 사용 코드인지, 초기 개발 단계의 코드인지 알려진 바가 없습니다. 보존된 원문을 임의로 고쳐 쓰지는 않습니다.

## 현재 실행용 복원 코드의 목적 일치 교정 (2026년 수정)

```python
if button == 1:
    result = 1
elif color_condition and people_num != 0:
    result = 0
else:
    result = previous_result
```

`raspberry_pi/main.py`는 **색 구간 AND 대기자 검출**을 새 정지 조건으로 사용합니다. Pi는 색상 센싱보다 **먼저 반복 촬영·검출을 수행**하고, 이후 Arduino가 전달한 정지구간 정보를 결합합니다. 정지구간에서의 최신 검출값이 0명이면 계속 주행하며, 1명 이상이면 정지합니다. **당시 Arduino·Pi 최종 원본을 찾았다는 뜻은 아닙니다.**

## 여전히 필요한 근거

- 색상 센서가 정지 지점 **앞선 구간에서 영상 분석을 시작**하도록 배치된 사실은 확인되지만, 조기 감지와 실제 정지 지점의 분리를 위한 정확한 코드/거리값은 미확보입니다.
- 카메라가 실제로 대기 위치만 촬영하도록 설치됐는지, 별도의 ROI로 사람 위치를 한정했는지 알 수 없습니다. 현 복원은 **카메라 영상에 검출된 사람을 해당 작업 구간의 대기자로 간주**하므로 촬영 범위가 넓다면 오판할 수 있습니다.
- 색 판정 기록 `r>=4 or r>=2*g or r>=2*b`는 `0:0:0`에서도 참입니다. RGB 변환·보정 코드의 최종 상태를 알 수 없습니다.
- 최종 Arduino/Pi 프로그램의 `0/1` 의미, 결과 전송 종료문자, 분석 지연에 따른 제어 시점은 원본 미확보입니다.

## 교정의 의미

기존 2026년 복원본에는 `색 조건일 때만 사람을 검출`하면서 `색 조건 자체로 정지`하는 문제가 있었습니다. 사용자 설명으로 AND 정지 조건을 보완한 뒤, 2023년 대화의 반복 `get_frame→detect→serial` 코드 흐름을 다시 확인하여 **색상 조건 이전에 반복 촬영·검출**하도록 2026년 복원본을 추가 수정했습니다. **2023년 실제 시험에서 같은 오류가 발생했다는 의미가 아닙니다.**
