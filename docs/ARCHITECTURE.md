# 구성 및 실제 메시지 방향

```text
바닥 적외선 센서(IRL/IRR) ─┐
색상 센서(TCS34725) ───────┼─> Arduino ── r:g:b:button + \n ─> Raspberry Pi
재출발 버튼(pin 3) ────────┘       │                                │
                                  │                                ├─ protocol.py
                        result 0/1│ <───────────────────────────────┤─ coordinator.py
                                  │                                │   ├─ decision.py
                               모터 PWM                              │   └─ vision.py (worker)
                               (5,6,9,10)                          │        ├─ camera.py
                                  │                                │        ├─ runtime/before.jpg
                           IR 라인 추종/정지                         │        └─ count_objects.detect()
                                                                   │           (HOG 대체)
                                                                   └─ 상태/로그
```

## 구분

**역사적 제어 규칙**: `decision.py`, `protocol.py`와 `.ino`의 IR 분기 및 모터 PIN 상수.

**현대식 보완 기능 (당시 코드가 아님)**: `vision.py`, `coordinator.py`의 비동기 촬영, 타임아웃 때 정지, 실패 시 정지, 버튼 입력 뒤 과거 비동기 결과 폐기.

## 처리 순서

1. Arduino가 색상·버튼 값을 전송하고 Pi의 응답을 기다린다.
2. Pi는 색상 구간을 인식하면 비동기 카메라 촬영을 요청한다. **색상 조건만으로도 즉시 0을 반환한다** (기록된 판단식 유지).
3. Pi는 `before.jpg`를 기록한 뒤 `count_objects.detect(...)` 대체 구현을 호출한다.
4. 감지 결과가 준비되면 다음 요청에 반영한다. 정지 결과는 `previous_result`에 남아 버튼 입력 전까지 유지된다.
5. 버튼 입력 1은 주행 허용을 우선하며, 약 1~3초 동안 정지 판단을 무시한다.
6. Arduino는 `1`일 때만 IR 신호로 주행하고, `0`·통신 오류·시간초과 시 모터를 멈춘다.

## 실제 과제와의 차이

과거 언급에 따르면 목표 위치보다 앞선 색상 구간에서 먼저 카메라 감지를 시작해 정지 위치 오차를 줄이는 방향이었습니다. 현재 확보된 판단식은 **색상이 감지되면 사람 유무와 관계없이 정지**시키므로 색상 구간 내에서 완전히 멈출 수 있습니다. 이 차이를 동작상 그대로 남겨 두었습니다. 실제 목표 지점까지 추가 주행하는 거리를 임의로 도입하지 않았습니다.

시리얼 `0`/`1`은 요청 ID가 없으므로 늦은 응답과 현재 요청이 엇갈릴 위험을 완전히 제거할 수 없습니다. 개행 확인·이전 버퍼 폐기와 짧은 응답을 활용하지만, 원본 프로토콜이 가진 한계는 남습니다.
