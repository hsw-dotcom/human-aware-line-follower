# 사용자 최종 확인 — Pi 사람 인식 / Arduino 정지구간

> 이 문서의 **역할 분담은 사용자 직접 확인**이며, 아래 실행 예시의 정확한 원본 코드는 2023년 파일 미확보로 **2026년 복원**입니다.

## 최종 역할 분담 (2026-10-31 사용자 직접 확인)

| 기능 | Raspberry Pi | Arduino |
|---|---|---|
| 카메라 촬영·Safe Watch 사람 검출 기능 재사용 | **담당** | 아니요 |
| 검출된 사람 수 → 이진 존재 여부 0/1 계산 | **담당** | 사람 수를 받거나 세지 않음 |
| TCS34725 색상으로 정지구간 판별 | 아니요 | **담당** |
| 사람 존재 플래그와 색상 구간을 결합해 정지 결정 | 아니요 | **담당** |
| IR 라인 추종, 모터 PWM | 아니요 | **담당** |
| 적재 완료 후 버튼 재출발 및 구간 잠시 무시 | 아니요 | **담당** |

따라서 **Pi가 최종 정지 명령을 계산한 것도 아니고, Arduino가 인원수를 넘겨받아 해석한 것도 아닙니다.**
Pi는 이진화된 **사람 인식 여부**를 제공했고, Arduino는 **정지구간 감지 시점에만 그 신호와 결합해 정지**합니다.

## 주행 중 작업 흐름

```text
Raspberry Pi                                 Arduino
------------                                 ------------
MJPEG 한 프레임 추출                          IR 센서 기반 주행 유지
Safe Watch 검출 함수로 사람 수 확인             TCS34725 정지구간 감지
인원수 0명 → 플래그 0  ----------------------> 사람 없음
인원수 1명 이상 → 플래그 1  -----------------> 사람 있음
                                             정지구간 && 사람 있음 → 모터 정지
                                             정지 상태 유지 → 적재 후 버튼 재출발
```

사람은 멀리서 먼저 인식하며, **그 즉시 정지하는 것이 아니라** 아두이노의 정지구간 센서가 해당 위치에 도달해야 멈춥니다.

## 통신 0/1의 정확한 의미

- **사용자로부터 확정된 것:** Pi가 사람 검출 결과를 **0/1로 변환**했고 Arduino에 **사람 수 자체를 보내지 않았음**.
- **사용자 직접 확인:** 0=사람 없음, 1=사람 있음. 최종 구현에서 Pi는 이 값만 Arduino에 전달했습니다.
- 별도 2023년 시험 스케치에는 **0=정지, 1=주행**인 버전도 있습니다. 이는 제어 신호 자체를 전송한 **다른 실험 단계**이며 이 역할 분담과 혼동하지 않습니다.
- **사용자가 직접 확인한 사람 인식값의 갱신 간격은 0.3초입니다.** 2023-11-24의 변경 시에만 송신 요구를 참고해 복원 Pi 코드는 최초 1회와 값 변경 시에만 ASCII 0/1을 송신합니다. **검출값 갱신 주기와 실제 시리얼 송신 주기는 동일하다고 확정할 수 없습니다.**

## 역사적 기록과 현재 복원 코드의 차이

- 과거 일부 대화에는 Pi에서 RGB·버튼을 받고 `색 OR 사람` 조건으로 결론을 내리는 코드가 존재합니다. 이는 **개발 실험 기록**이며, 이번 사용자 직접 확인한 최종 역할 분담과 다릅니다.
- 현재 `raspberry_pi/main.py`는 **사람 인식 + 0/1 변환·송신만**, `arduino/line_tracer/line_tracer.ino`는 **색상 센서·IR 제어·버튼·정지 상태**만 처리하도록 분리했습니다.
- 바닥색은 라벨·테이프 재질에 따라 달랐고, **센서의 색 기준도 재질에 맞춰 변경**했습니다. Arduino 복원의 `r >= 5` 역치와 `2000ms` 무시 시간은 과거 실험을 참고한 선택값일 뿐, **실제 최종 색 조건과 무시 시간은 미확인**입니다.
- 이전 파일에 있던 `r >= 4 or r >= 2*g or r >= 2*b` 및 Pi가 `result=0/1`을 직접 판단하는 코드는 역사적 논의 기록으로 남기되 **최종 역할 분담의 실제 구현이라고 주장하지 않습니다**.
- 아직 실장 원본 코드와 카메라 ROI, 검출값 유지 방식 및 송신이 끊겼을 때 처리 방식을 확보하지 못했습니다.

## 검증 범위

Python의 인원수→0/1 변환·전송 테스트와 상태 전이 시뮬레이션은 **Arduino 물리 구동이나 실제 2023년의 통신 프로토콜 시험을 대체하지 않습니다**.

## 2026-10-31 사용자 추가 확인 5항목

1. **사람 인식값 갱신 주기: 0.3초.** 결과는 해당 주기마다 갱신·판단합니다. 현재 실행용 복원은 0.3초 목표 주기를 적용하되, 추론이 300ms를 넘으면 다음 갱신이 지연될 수 있습니다.
2. **0/1 의미 확정:** `0=사람 없음`, `1=사람 있음`. Arduino에는 인원수 전체가 아닌 이진 존재 신호만 전달합니다.
3. **정지구간 표시 방식:** 바닥에 라벨 또는 테이프를 부착하여 서로 다른 색상의 구간을 만들었으며, **재질에 따라 색 판정 기준을 변경**했습니다. 한 가지 고정 RGB 수치가 최종 기준이었다고 주장할 수 없습니다.
4. **정지 유지:** 정지구간에서 사람이 인식돼 정지한 다음에는 사람이 시야에서 사라지더라도 **버튼을 다시 누르기 전까지 계속 정지**합니다.
5. **재출발 후 무시 범위:** 일정 시간 동안 **사람 인식 신호와 색상 정지구간 조건 모두 정지 판단에서 무시**합니다. 이 기간에는 IR 라인트레이싱만 진행합니다. Pi 카메라 자체까지 껐다는 근거는 없으므로, 실행용 복원은 촬영을 유지하되 Arduino의 정지 조건 평가만 생략합니다.

**근거 경계:** 0.3초의 갱신 주기와 신호 극성, 색 재질 조정, 정지 유지 및 두 조건 무시는 사용자 직접 확인입니다. 반면 현재 코드의 `r>=5`, `IGNORE_MS=2000`, 값 변화 시에만 시리얼 전송, 프레임마다 `VideoCapture` 재연결은 복원 선택이거나 과거 개발안이므로 동일하게 확정하지 않습니다.
