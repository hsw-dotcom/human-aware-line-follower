# 코드 경계조건 및 예상 동작

## 최종 판단식의 진리표

| 버튼 | 색상 | 인식 사람 수 | 이전 응답 | 이번 응답 |
|---|---:|---:|---:|---:|
| 1 | 무관 | 무관 | 무관 | 1 |
| 0 | 참 | 0 | 1 | 0 |
| 0 | 거짓 | 1 이상 | 1 | 0 |
| 0 | 거짓 | 0 | 0 | 0 (정지 유지) |
| 0 | 거짓 | 0 | 1 | 1 (주행 유지) |

## 버튼 재출발

`Controller`는 버튼의 **눌림 순간**에만 무시 시간 계산을 시작합니다. 버튼을 누른 채 유지해도 무시 구간을 무한 연장하지 않습니다. 버튼이 눌린 동안에는 `1`을 전송하는 우선조건이 유지됩니다. 이 구현은 대화에서 확인한 '재시작 버튼 1~3초 무시' 요구에 대한 합리적 복원입니다.

## 0:0:0 문제

기록된 색 조건식 `r>=4 OR r>=2*g OR r>=2*b`는 `0:0:0`에서도 `0 >= 0`이 성립합니다. 무조도·센서 오류에서 정지하는 쪽으로 동작하지만, 해당 값만으로 '적색 바닥'이라고 해석하면 안 됩니다. 테스트는 원식을 그대로 유지합니다.

## 시리얼 응답과 카메라 처리

영상 분석은 몇 백 밀리초를 넘길 수 있어 `.ino`의 응답 대기를 자주 초과할 수 있습니다. 재구성 보완판은 촬영·검출을 하나의 워커 스레드로 분리했습니다. Pi는 Arduino에 먼저 즉시 답하며, 다음 사이클에 최신 영상 결과를 사용합니다. 검출 중에도 정지하도록 `stop_while_inflight=true`를 기본값으로 둡니다.

Arduino는 한 요청에 한 개의 0/1 완성 응답만 허용하고 시간 초과 시 STOP합니다. 기존 메시지에는 패킷 ID가 없기 때문에 USB 재시작·바이트 지연 등에서 완전한 동기화가 불가능합니다.

## 사람 감지 위치와 성능

과거 대화는 '사람이 지정 작업 구역에 있는가'를 묻는 동작과 3~5m 인식 사례를 설명합니다. 이 ZIP에는 그때 사용했던 모델 원본·ROI/임계값이 없어 범용 OpenCV HOG 검출기만 대체로 들어 있습니다. 실제 재현에는 원본 학습 모델 또는 별도 검증된 모델을 연결해야 합니다.

## 잠금된 정지의 의미

색 구간이나 사람이 한 번 감지되면 `previous_result=0` 상태를 유지합니다. 색을 벗어나거나 카메라에서 사람이 사라지더라도 자동 출발하지 않습니다. **버튼으로 재출발해야** 합니다. 원래 대화의 `result=previous_result`를 반영한 것이며 이 안전한 동작을 임의 변경하지 않았습니다.
